# トークン効率ルール

## 基本方針

- 最小の読み取り専用確認から始め、得られた証拠に応じて調査範囲を広げます。
- コマンド出力は必要箇所だけ取得します。quietオプション、対象の絞り込み、`tail`などを使い、依存関係の取得ログや成功済みタスクの全量を読み込みません。
- 長いログはファイルへ保存し、エラー周辺や末尾だけを確認します。原因特定に必要な場合だけ範囲を広げます。
- 成功済みの高コストな処理は、その結果へ影響する変更がない限り繰り返しません。
- 完全なBuild、Lint、統合テストは、対象確認が通った後の最終検証としてまとめて実行します。
- Docker、Gradle、SDKのキャッシュを維持し、診断のためだけに再構築や再取得を行いません。
- 高コスト処理を再実行する前に、新たに確認できる事実を明確にします。同じ結果しか得られない再試行は行いません。

## 報告

- 途中報告は、判明事項、次の確認、ブロッカーだけを簡潔に伝えます。
- 最終報告には、変更内容、実行した確認、未実施の確認と理由を記載します。長いコマンド出力は転載しません。

## 優先順位

ユーザーの明示指示、正確性、安全性、リポジトリの完了条件を優先します。必要な検証を省略するためにこのルールを使用してはいけません。
